# 报价单生成器最小实现记录（2026-06-26）

## 背景

报价单用于招生或续课前的课程费用预估。它通常覆盖未来 4-5 个月，也可能覆盖更长周期；输出形态接近旧 Excel/PDF 模板，用于让学生或家长看到每个月、每周、每门课的大致课时安排和总价。

当前 v2 实现目标是替代手工 Excel 复制粘贴，先把可操作的报价单生成出来。报价通过并不等于业务已经形成；是否将报价转换成正式预定课时，未来需要单独设计。

## 当前实现

- 版本：`v10.3.23`
- 页面：`quote-plan.html`
- 入口：报价页侧边栏独立入口，不放入学生、课时、结算等既有业务分组。
- 前端入口：`js/quote-plan-app.js`
- 页面逻辑：`js/pages/quote-plan-page.js`
- 样式：`css/app.css`

当前实现为 v2 最小可用工具。它不读取系统内学生、科目、老师、业务归属，也不把报价结果保存为课时、结算、收入或 Cash 数据。这是本次最小实现边界，不作为 v3 长期规则沉淀。

## 输入项

- 学生姓名：手动输入，不引用系统学生档案。
- 文件标题：默认 `课程计划`。
- 开始日期 / 结束日期：用于生成报价周期内的每周计划。
- 内部汇率：用于 CNY 参考金额计算，打印版不显示。
- 备注：可选，显示在报价单底部。
- 课程目录：
  - 课程名
  - 显示内容
  - 每次时长（H）
  - 每周次数
  - 内部单价（JPY/H），打印版不显示

## 输出规则

- 输出按月份拆分，每个月生成一张报价表。
- 每个月内按课程分组显示：先显示某一课程的全部行，再显示下一课程。
- 课程分组顺序按输入课程目录顺序。
- 组内按周一日期顺序排列。
- 打印版表格列为：科目、日期、回数、内容、时长（H）。
- 月底显示月度课时、月度 JPY 合计、CNY 参考合计。
- 单价和汇率只参与计算，不显示在报价单打印内容中。

## 业务规则

1. 报价计划不指定具体上课日和上课时间，只按每周生成课程计划。
2. 每周以周一日期作为周的锚点，日期显示为 `M.D周`。
3. 跨月周的归属月份以该周周一日期为准。
4. 每门课程独立累计回数，从报价开始到结束连续编号。
5. 同一课程每周多次时，在同一周一锚点下生成多条记录，并连续累计回数。

## 与正式业务链路的关系

当前报价单不是正式预定课时，不参与学生结算、老师工资、收入、Cash 或任何锁定链路。

如果未来需要把报价转换成正式预定课时，必须作为单独功能设计，并重新确认：

- 是否允许一次性生成多个月预定课时；
- 如何避免重复生成；
- 生成后是否允许撤回；
- 如何处理 v2 预定课时作为业务基础数据、不轻易删除的规则；
- 是否需要学生、科目、老师、业务归属映射；
- 是否进入学生月度结算和后续锁定链路。

## 后续可观察点

- 旧 PDF 版式是否还需要进一步贴近原模板。
- 是否需要导出文件名规则。
- 是否需要更多课程预设模板。
- 是否需要按文科 / 理科方案快速生成课程目录。
- 真实使用 2-3 次后，再判断是否需要进入 v3 的正式报价模块设计。
