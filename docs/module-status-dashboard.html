状态标签说明

  • 已收口当前 V1 目标已经完成并有文档记录，后续只做独立新阶段或缺陷修正。
  • V1 可用核心读写链路已经可用，但仍有明确的后续增强、补充页面或扩展范围。
  • 只读/预览当前模块主要提供列表、详情、预览或审计查看，本模块自身不发起写入。
  • 需要验证repo/docs/code 里能看到入口或边界，但还需要单独复核后才能标为已完成。
  • Backlog已明确暂不实现，或必须另开 guarded workflow 的事项。

编辑范围优先按当前 repo/docs/code 中可验证的 RPC、API 层和页面实现统计。RPC、表名、字段名和文件名保留英文并以 code 显示；不确定的编辑范围标为“需要进一步验证”。

课时管理

已收口
完成度13/13
当前状态
课时管理 V1 基本收口。预定/实际 V1、受保护编辑、仅预定导入、仅预定作废已经形成可运营链路。
V1 边界
planned-only 导入是当前核心稳定源头；当前 v2 普通新增/导入仍保持 planned-only，不恢复 v1 那种普通新增时自由选择预定/实际的宽入口。实际生成、取消、补课完成和 linked actual 编辑都依托 planned 源头及其保护语义。生成实际课时后如有问题，当前运营优先通过 guarded edit 修正，而不是删除重建。
已完成
列表/详情、预定/实际配对视图、预定新增、三类从预定生成实际、跨月补课完成登记、受保护编辑、预定作废、已作废只读查看、导入预览/模板/提交、返回筛选导航、结算/工资证据链接。
写入入口
通过 js/api/lesson-api.js 调用已验证 RPC：预定新增、三类实际生成、跨月补课完成、仅预定批量导入、受保护编辑、仅预定作废。
保护规则
保护已锁定学生结算月、已锁定老师工资月、关联实际/来源一致性、过期 updated_at、已作废行、工资明细快照和空原因。
历史数据
当前不处理历史数据；历史维护由 v1 或单独 migration/backlog 处理。full actual import 保持 future/history migration backlog。
跨月补课
已完成 DB/RPC + API/UI V1。独立入口从补课月份打开，只列出以前月份、未作废、无 linked actual 的 pending_makeup planned；默认不计费且金额固定 0，在补课月份生成 makeup_completed actual，planned_lesson_id 指向原 planned，不复制 planned/actual，不修改来源 planned。原月份显示“已于 YYYY-MM 完成”，补课月份显示“来源：YYYY-MM 待补课”。
未完成
自由实际新增、完整实际导入、课时删除、作废恢复、voided_by、从课时生成工资锁定、自动匹配、同文件预定/实际关联。lesson delete 仍是 backlog，但当前不是刚需。
